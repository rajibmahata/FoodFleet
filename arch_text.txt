Customers open the app, their nearest branch is detected via GPS, they browse that branch's available menu, build a cart, provide a delivery address validated against the branch's configured delivery radius, select a payment method, and place the order. The platform is built API-first with a single .NET 8 backend serving a Blazor WebAssembly customer web app, a React Native mobile app, and a Blazor Server admin panel.1.1 Application SuiteAppTech StackAudiencePurposeCustomer Web AppBlazor WebAssembly (.NET 8)End customersBrowse, order, checkout via browserCustomer MobileReact Native + ExpoEnd customersiOS & Android ordering appAdmin PanelBlazor Server (.NET 8)Restaurant ops staffManage branches, menus, orders, settingsBackend API.NET 8 Web APIAll clientsCentral business logic & data1.2 Core User JourneyApp opens → restaurant branding & splash screenLocation: GPS auto-detects nearest branch OR manual dropdown selectionMenu loads: items filtered to selected branch, out-of-stock items hiddenCustomer builds cart, reviews orderCheckout: enters delivery address (map pin or typed)Geo-validation: address checked against branch delivery radius (default 3 km) — order blocked if outside rangePayment: UPI / Razorpay / Stripe / Cash on DeliveryOrder confirmed: customer sees delivery partner name + phone numberCustomer can call delivery partner directly for status updates (no live tracking)1.3 System Flow DiagramsThe three diagrams below show how the platform works from each perspective: the end customer, the restaurant admin, and the technical system. SQLite is unsuitable for multi-user concurrent writes, lacks robust JSON support, and cannot be hosted on Azure PaaS services. PostgreSQL handles concurrent orders, complex geo-queries, and scales cleanly from a single VPS to Azure Flexible Server with no schema changes.2. Location & Geo-Validation3.1 Branch Selection FlowApp opens → request GPS permissionGPS granted: device coordinates sent to GET /api/v1/branches/nearest?lat=&lng= → nearest active branch auto-selectedGPS denied: dropdown of all active branches shown; user selects manuallyUser can always override branch selection from header dropdown3.2 Delivery Radius RulesCRITICAL RULEAn order cannot be completed if the delivery address falls outside the branch's configured delivery radius. This is enforced server-side at order placement. Client-side validation is for UX feedback only and cannot be bypassed.Default Radius3.0 km from branch coordinates (if not configured in admin)Admin OverrideAdmin can set any radius per branch (e.g. 5 km, 10 km) from the Branch Settings pageAlgorithmHaversine formula — great-circle distance between branch lat/lng and delivery lat/lngValidation Timing1) Real-time as customer types/pins address (UX feedback)  2) Enforced again at POST /api/v1/ordersOut-of-Range BehaviourCheckout button disabled; message: 'Delivery not available. This branch delivers within X km.'API EndpointPOST /api/v1/geo/validate-delivery  →  { isDeliverable, distanceKm, radiusKm }Error on OrderHTTP 422 Unprocessable Entity if address fails radius check at order placement3.3 Geo-Validation API ContractRequest — POST /api/v1/geo/validate-deliveryBody: { "branchId": "uuid", "deliveryLat": 22.5726, "deliveryLng": 88.3639 }Success Response (200):{ "isDeliverable": true, "distanceKm": 1.84, "radiusKm": 3.0 }Out-of-Range Response (200):{ "isDeliverable": false, "distanceKm": 4.62, "radiusKm": 3.0 }4. Payment System4.1 Supported Payment MethodsArchitecture NoteAll gateways implement IPaymentGateway. Active gateways are determined by which ones have credentials configured in RestaurantSettings. If a gateway has no API key, it does not appear at checkout.GatewayTypeIntegrationNotesUPI (via Razorpay)Digital — IndiaRazorpay .NET SDKVPA input or QR code; primary India methodRazorpay (Cards/Wallets)Digital — IndiaRazorpay .NET SDKNet Banking, Debit/Credit Cards, Paytm, PhonePeStripeDigital — InternationalStripe .NET SDKCards, Apple Pay, Google PayCash on DeliveryOfflineInternal (no API call)Order confirmed immediately; payment on delivery4.2 Payment FlowCustomer selects payment method — only methods with credentials in RestaurantSettings shownPOST /api/v1/payments/initiate → Order created (status: PendingPayment), gateway session/token returnedClient opens gateway SDK / UPI QR / hosted checkoutGateway calls webhook → API verifies signature, updates Payment + Order statusPOST /api/v1/payments/confirm → client confirms with gateway reference; API performs final syncOrder status moves to Confirmed; delivery partner assigned if availableCustomer receives confirmation with delivery partner name and phone number4.3 COD FlowCustomer selects Cash on DeliveryPOST /api/v1/orders → Order created with status Confirmed, PaymentMethod = CODNo gateway call; Payment record created with status PendingOn delivery: admin marks order as Delivered and payment as Collected5. Settings & Configuration System8.1 Design: Key-Value Config StoreAll platform behaviour is driven by the RestaurantSettings table (Key / Value pairs). Features are only active when their configuration keys are present and valid. The platform can be deployed for any restaurant without code changes.PrincipleIf a payment gateway has no API key configured, it does not appear at checkout. If email SMTP is not configured, no emails are sent. If SMS credentials are absent, no SMS is sent. Nothing breaks — the feature is simply inactive.8.2 Configuration CategoriesCategorySetting KeyDescriptionRequired?Restaurantrestaurant.nameDisplay name shown in app and emailsYesRestaurantrestaurant.logo_urlLogo image URLRecommendedRestaurantrestaurant.contact_emailContact email for supportYesDeliverydelivery.default_radius_kmDefault radius if branch has none set (default: 3.0)YesPaymentpayment.razorpay.key_idRazorpay Key ID — enables UPI + RazorpayOptionalPaymentpayment.razorpay.key_secretRazorpay Key Secret (encrypted at rest)OptionalPaymentpayment.stripe.publishable_keyStripe Publishable KeyOptionalPaymentpayment.stripe.secret_keyStripe Secret Key (encrypted at rest)OptionalPaymentpayment.cod_enabledtrue/false — enables Cash on DeliveryOptionalEmailnotification.email.enabledtrue — activates order email notificationsOptionalEmailnotification.email.smtp_hostSMTP server hostIf email enabledEmailnotification.email.usernameSMTP username / API keyIf email enabledEmailnotification.email.from_addressFrom address for order emailsIf email enabledSMSnotification.sms.enabledtrue — activates order SMS notificationsOptionalSMSnotification.sms.providerProvider: twilio or fast2smsIf SMS enabledSMSnotification.sms.api_keySMS provider API key (encrypted at rest)If SMS enabled8.3 Notification EventsEventEmailSMSOrder PlacedOrder summary + items + delivery partner contact'Your order #XYZ has been confirmed.'Order Preparing'Your order is being prepared'Short status SMSOut for DeliveryPartner name + phone number'Your order is on the way. Security ConsiderationsHTTPS enforced at Nginx; HTTP redirectedJWT signed RS256 (admin), HS256 (customers); short-lived access tokens (15 min) + refresh rotationAll payment gateway secrets and SMTP passwords encrypted via ASP.NET Core Data Protection before DB storageGeo-validation enforced server-side at order placement — client-side is UX only and cannot be bypassedPayment webhook endpoints validate gateway signatures before processingRole-based authorization: Customer, BranchManager, Admin rolesRate limiting on auth endpoints via .NET rate limiter middlewareCORS restricted to known client originsImport endpoint: file size limit (5 MB max), extension whitelist (.xlsx only), row count cap (500 rows)NotificationLog records all outbound email/SMS for audit and replay capability— End of Document  |  FoodFleet Platform v2.0 —
